# Repository Instructions

## Commit messages

- Use a Conventional Commits-style header: `<type>(<optional scope>): <imperative summary>`; the scope is optional.
- Choose an accurate type such as `feat`, `fix`, `docs`, `test`, `refactor`, `build`, `ci`, or `chore`.
- Keep the subject concise, specific, imperative, and without a trailing period; avoid vague subjects such as “updates” or “changes”.
- For non-trivial commits, follow the header with a blank line and a detailed body explaining what changed and why; bullets are acceptable, with readable wrapping.
- Include validation performed in the body or in a `Tests:`/`Verification:` footer.
- Use a `BREAKING CHANGE:` footer when applicable.
- Inspect status and diff, keep scope intentional, and do not sweep unrelated user work into a commit without explicit authorization. Explicit user instructions can override this default.
