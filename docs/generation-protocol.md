# Generation protocol

Generation and judge templates are files in `prompts/generation/` and
`prompts/judge/`. Their versions and SHA-256 hashes are recorded in the generation plan
and provider traces. The generation prompt contains only a TRAIN-only profile and an
optional deterministic class-aware reference sample; it requests a JSON array and
forbids external factual fabrication.

`GenerationPlan` makes requested count, class strategy (`preserve_reference` or
`explicit`), quotas, objective, profile ID/hash, generator config, batch size, seed,
and prompt version/hash explicit. Preserve-reference resolves deterministic
TRAIN-proportional quotas; explicit quotas are validated against TRAIN labels and zero
quotas are omitted. The resolved quotas are scheduled as deterministic per-class
batches, so each provider call has one concrete requested class and count.
`minority_augmentation` is represented as a planned objective but is not executable in M1.

`ReplayGenerator` and `OpenAICompatibleGenerator` are concrete generation-facing
adapters over the shared role-aware provider call API; the API intentionally traces
batched raw responses rather than the legacy one-record async protocol. Replay responses
are consumed deterministically from a fixture. The OpenAI-compatible
adapter requires a configured endpoint/model and optional API-key environment variable;
it never hardcodes a public endpoint. Every call records provider, model, sanitized
endpoint, rendered prompt/raw response, prompt hash/version, concrete request class/count,
temperature/max tokens, seed, usage, latency, nullable cost, timestamp, and replay source
ID. Failed attempts remain accounted by failure events. Keys are never written to artifacts.

Raw responses are persisted before parsing. The parser accepts only JSON arrays of
objects, retains the raw output on every candidate/failure, and records malformed JSON,
wrong shapes, and partial item failures. Candidates are never clipped, imputed,
category-corrected, logically rewritten, or regenerated by this protocol. Exact
canonical duplicate hashes are computed separately from stored candidate data.
